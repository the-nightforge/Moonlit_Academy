# Game review improvements — accepted scope

The user selected priorities 1, 2, 3 and 5 from the final priority table in the overall game review, and explicitly confirmed this numbering. Work stays on main. Existing arena full progression, power matching, undisclosed sixty-second fallback and normal ranked settlement remain unchanged.

1. Make the three reproduced combat rules reliable: Tần Sương's Hàn Kiếm applies to actual opponents in every mode; Điệp Vũ's Vũ Điệp gives one extra damage to her own attack cards after her first own attack that turn; co-op heroes receive the existing round-twenty fatigue policy. Preview and actual damage agree, and state resets even for temporarily fallen heroes.
2. Reduce actual image bytes and prepare only the team/battle assets needed for entry. Retain original art; optimize encoding without cropping, stretching or changing style. Progress, retry and scene shutdown remain safe. Complete the concrete image, control, focus, modal, settings, hero detail and persistent-error gaps identified by review. Follow docs/ui-rules.md, including permitted overlays and rounded bordered controls.
3. Give a new player a short story-led first session: context for finite cards, moon and awakening; a verified first victory; one free card choice and an explicit same-owner replacement in a saved deck; use that changed deck in a subsequent story fight. Server validates and persists reward/lesson state, enforces one claim, preserves earned unlock credits and existing profiles, and resumes after reload. Registration points to this flow instead of gacha.
5. Make repeated play meaningfully different: surviving heroes cannot leave a victory below the recovery floor given to fallen heroes; rotate at least three seeded run bosses; add three events with real choices and safe exits; offer controlled, run-only swaps from the selected heroes' unlocked card pool. Keep eight floors and an accessible rest before the boss. Cleared story stages allow verified replay without duplicate first-clear rewards and dialogue-only reading. Add three hero-independent co-op combinations, preserving existing priority and consumption rules.

All rules and tickets remain deterministic and server-authoritative. Run card availability is captured at ticket creation. New profile fields are backward compatible; imports cannot forge onboarding claims. No economy/gacha redesign, PvP reward reversal, phone-specific redesign or fabricated player testing belongs to this scope. New run encounters reuse existing enemy definitions and their artwork. Update the engine fingerprint once for the combined rule changes.

Verification uses meaningful focused regressions, relevant existing tests, schema/data checks, workspace typecheck, production client build and independent review. Browser checks are reported separately; unit tests do not imply live visual or human playtest acceptance.
